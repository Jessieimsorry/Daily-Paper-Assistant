# 升级、迁移与恢复

## 常规升级

下载 Releases 的新版 ZIP，完整解压到新文件夹，双击对应系统的启动脚本。不要把新文件直接覆盖到一个仍在运行的旧版目录。

程序识别版本与程序内容。已经是当前版本时直接打开原页面；同一固定数据目录中的资料会继续使用。旧版支持安全切换且当前无后台任务时，新启动器会自动停止旧服务、备份、切换和打开新版。

2.0 等早期版本没有安全退出接口，需要先关闭旧启动窗口。若工作台由系统后台服务管理，请先停止该后台服务；启动器不会强行结束未知进程或更改系统服务。

有采集、模型或排队任务时先完成或取消任务，再启动新版。端口属于其他程序时不会停止对方。

## 数据在哪里

- Windows：`%LOCALAPPDATA%\DailyPaperAssistant\data`
- macOS：`~/Library/Application Support/LitDesk/data`
- Linux：`~/.local/share/daily-paper-assistant/data`，可受 `XDG_DATA_HOME` 影响。
- 使用 `LITDESK_DATA_DIR` 自定义位置的用户，升级时仍需使用同一设置。

文献库、收藏、解读、译文、阅读记录、模型密钥及上传资料均在数据目录中。资料不会上传到 GitHub。

## 更早的版本把资料留在旧文件夹里

先关闭旧版。在新版解压目录打开终端，运行：

```text
node scripts/launch.js --from "旧版的完整路径/data"
```

目标数据目录为空时，会检查数据库、保留旧资料、复制完整数据并启动。资料恰好在新版文件夹的 `data` 子目录时，会自动识别。

如果目标位置和旧文件夹里都有资料，启动器会停止迁移，不覆盖任何一份。可分别启动旧、新工作台，在“任务与数据”使用 JSON 导出和预览合并导入。JSON 不包含密钥或上传的全文文件，两份完整目录都应保留，不能仅靠 JSON 当作完整备份。

## 备份与失败恢复

每次实际升级，在应用支持目录的 `backups/时间编号/` 保存完整 `data/`、旧 `program/` 和 `upgrade.json`。备份含密钥和个人资料，只能自行保管，不要上传到问题反馈。

仅在服务停止后复制数据库和 WAL，备份通过 SQLite 完整性检查后才切换程序。新版启动失败时，恢复升级前的数据与程序；失败现场保留在 `.failed-时间` 目录，便于排查。旧程序存在时会尝试重新启动。

如果自动恢复也不能启动：关闭工作台，保留当前整个数据目录，把所选备份中的完整 `data/` 恢复到原位置，并使用对应旧版本程序。不要只复制主数据库而混入另一版本的 WAL 文件。不要在程序运行时覆盖数据。启动器拒绝直接用更旧安装包覆盖新程序。

启动时如提示另一个升级正在进行，请稍后重试。异常断电后需保留备份再排查，不要随意删除正在使用的升级锁或数据文件。

## 当前边界

2.1 实现下载新包后的升级与迁移，不会在后台自动下载安装程序。固定资料目录能自动沿用；任意磁盘角落里的旧副本需要用 `--from` 明确指定。网络共享仍须有正常读写权限。
