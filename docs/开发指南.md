# 开发与发布

- `server.js`：本机 HTTP 入口；`lib/`：存储、采集、模型和业务逻辑。
- `public/`：无构建步骤的前端；`catalogs/`：公开主题及空目录模板。
- `scripts/launch.js`、`scripts/upgrade.js`：启动、备份、迁移和切换。
- `test/`：隔离数据测试，不应对个人数据运行破坏性检查。

使用 Node.js 24 LTS，执行 `npm ci --ignore-scripts`，然后 `npm test`。完整启动与升级检查分别执行 `node test/launcher-integration.js` 和 `node test/upgrade-integration.js`，三平台 CI 都执行。Windows 还运行浏览器布局检查。

先运行 `npm run release` 生成白名单发布副本并检查隐私，再运行 `npm run package` 生成 `dist/` 中的精简用户目录。用户包不含测试、开发工作流、私人资料或 Git 历史；压缩后发布到对应版本的 GitHub Release。每个正式版本必须同时修改 package.json 和锁文件版本。

`release/`、`dist/` 和生成的发布清单不提交仓库。校验清单随正式安装包提供。升级控制令牌仅保存在本机应用支持目录，不进入发布包。
